# Как показать автономную альтернативу

Для команды и защиты, 7 сентября 2026. Основной тренажёр с API остаётся текущим продуктом. Отдельный [локальный стенд](http://127.0.0.1:8898) проверяет голос и лицо без внешних сервисов. Запуск и перенос: [README демо](../demos/offline/README.md).

## Показ за две минуты

1. Открыть стенд заранее, дождаться загрузки лица. «Это отдельная проверка локального исполнения. Сейчас я ввожу текст сам, LLM и микрофон здесь не подключены».
2. Выбрать Piper, нажать «Клиент», затем «Произнести». «Голос создаётся на этом компьютере, без отправки текста провайдеру».
3. В середине нажать «Остановить». «Воспроизведение прерывается сразу, поздний результат не может снова запустить звук. Голосовое перебивание ещё предстоит подключить».
4. Попросить аудиторию предложить короткую новую фразу, ввести её. «Это не заготовленный ролик. Слова новые, изображения для лица подготовлены заранее».
5. Выбрать Silero и произнести ту же фразу для сравнения. Не объявлять победителя заранее: оценить голос и губы на слух и глазами.
6. Прокрутить к трём шагам алгоритма. «Мы можем убрать облачные зависимости. Компромисс текущего прототипа: менее разнообразная мимика и конечный набор движений».

При желании отключить Wi-Fi после загрузки страницы и повторить с новой фразой. Сам сервер должен оставаться запущенным. Не путать отсутствие интернета с выключенным локальным сервером.

## Что сказать за минуту

«Мы отдельно проверили вариант для закрытого контура. Текст превращается в русскую речь локальной моделью. Небольшая модель анализирует звук, а браузер выбирает подходящие изображения лица по времени аудио.

Тяжёлая генерация изображений выполняется один раз при подготовке персонажа. Для новых фраз не нужен онлайн-доступ к GPU и не нужно заранее записывать все возможные ответы. В нашей библиотеке сто положений головы и шестьдесят четыре формы рта для каждого.

Сегодня реально работает ввод текста, два локальных голоса и остановка воспроизведения. Полный разговор требует добавить локальное распознавание, языковую модель и управление очередью реплик. Мы описали, чем заменить каждый внешний компонент, но не выдаём эту сборку за уже готовый автономный тренажёр.

Этот подход полезен, когда разговоры нельзя передавать облачным провайдерам. Качество губ и мимики пока ниже нашего продуктового ориентира и требует человеческой проверки».

## Что уже проверено

| Проверка на текущем Mac | Результат |
|---|---|
| Новые фразы | 3 русских текста каждым из двух TTS, без кэша |
| Piper, вся подготовка | 0,80–1,30 с для 5,15–6,33 с звука |
| Silero, вся подготовка | 1,61–2,11 с для 5,39–6,79 с звука |
| Анализ звука аудиодрайвером | 7–14 мс на этих шести коротких записях |
| Браузер | Декодирование и запуск обоих голосов, остановка, поздний ответ, ещё одна новая фраза |
| Внешние запросы страницы | 0; тест блокировал все адреса кроме локального стенда |
| Затраты внешних API | 0 вызовов, 0 ₽ |

Это небольшой функциональный тест, не статистика p95 и не обещание задержки на чужом ноутбуке. Время включает запуск TTS-процесса и загрузку модели. Полный WAV готовится до воспроизведения. Повтор уже рассчитанного текста явно отмечен как кэш.

Вызов остановки в тестовом браузере занял около 1–2 мс. Это время обработчика JavaScript, не акустический замер: в него не входят микрофон, VAD, звуковое устройство и его буфер. Исходные числа: [metrics.json](../artifacts/runs/17_offline_defense/metrics.json), [browser.json](../artifacts/runs/17_offline_defense/browser.json).

## Почему не нужно генерировать видео для каждой фразы

1. До показа модель DH Live создаёт варианты рта для каждого положения головы. Готовый набор занимает около 107 МБ по предыдущему измерению. В этом прогоне его не пересчитывали.
2. Во время показа TTS выдаёт PCM-аудио. Локальный ONNX-аудиодрайвер преобразует его в шесть управляющих значений на каждый момент времени. Это не таблица «буква равна картинке».
3. Подбирается ближайшее состояние с учётом соседних состояний. Canvas совмещает область рта с базовым кадром. Рот следует времени аудио; голова движется отдельно и плавнее.

Графический учитель использован только при подготовке. Алгоритм библиотеки и проигрыватель собраны нами поверх готовых моделей. Мы не обучали новую фундаментальную модель. Подробности: [алгоритм](../artifacts/runs/07_avatar_graph/ALGORITHM.md), [история предрасчёта](../artifacts/runs/07_avatar_graph/README.md).

Конечный набор движений ограничивает реализм. Увеличение числа картинок не исправит фонетическую ошибку исходного аудиодрайвера. Новые эмоции и свободные повороты требуют новых данных либо другого представления лица.

## Чем заменить API в полном тренажёре

Ниже проектируемая схема. Эти блоки не соединены в автономный разговор в данном демо.

| Задача | Локальное решение | Как используем |
|---|---|---|
| Замечать начало речи | [Silero VAD](https://github.com/snakers4/silero-vad) | На сервере; сразу выдаёт сигнал отмены. Не ждём распознанных слов |
| Понимать конец реплики | [Smart Turn v3](https://github.com/pipecat-ai/smart-turn) | После паузы проверяет контекст последних, максимум, 8 с аудио; не задерживает начало прерывания |
| Распознавать русский | [faster-whisper](https://github.com/SYSTRAN/faster-whisper) | Для первой CPU-пробы small/int8; качество и задержку проверяем на наших разговорах |
| Играть роль клиента | [Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B) и [llama.cpp](https://github.com/ggml-org/llama.cpp) | Локальные веса; режим без рассуждений, короткий контекст сценария, поток текста |
| Озвучивать | Piper, затем Qwen3-TTS | Сначала контрольный CPU-вариант, затем проверка более выразительной речи |
| Показывать лицо | Текущий атлас, затем FeatherTalk или MuseTalk | Выбор зависит от доступного железа и человеческой оценки |
| Вести обучение | Наши сценарии, состояние целей и локальная БД | У роли своя позиция. Оценку и подсказки отделяем от речи персонажа; отчёт с цитатами после разговора |

Pipecat можно сохранить как оркестратор, заменив сервисы локальными адаптерами. Его облако не обязательно для LocalSmartTurnAnalyzerV3. Qwen3 поддерживает `enable_thinking=False`; это отключает рассуждения, но само по себе не гарантирует малую задержку. [Smart Turn: локальный запуск](https://github.com/pipecat-ai/smart-turn#with-local-inference), [Qwen3: режимы](https://huggingface.co/Qwen/Qwen3-4B#switching-between-thinking-and-non-thinking-mode).

Для GPU без интернета: однажды перенести веса, зависимости и данные. Если машина доступна по внутренней сети, модели можно вызывать внутри неё. Если она вообще не связана с ноутбуком, используем её только для предрасчёта и переносим результат; онлайн-диалог на неё не рассчитывает.

## Альтернативы голоса

| Решение | Зачем пробовать | Ограничение и статус |
|---|---|---|
| [Piper](https://github.com/OHF-Voice/piper1-gpl) | Простая CPU-озвучка, небольшой локальный пакет | Дмитрий реально проверен; выразительность оцениваем людьми. Код GPL-3.0, [карточка датасета голоса](https://huggingface.co/rhasspy/piper-voices/blob/main/ru/ru_RU/dmitri/medium/MODEL_CARD) указывает CC0 |
| [Silero v5.5](https://github.com/snakers4/silero-models) | Русские голоса; сравнение качества на том же тексте | Евгений реально проверен. [CC BY-NC-SA 4.0](https://github.com/snakers4/silero-models/blob/master/LICENSE), не свободная коммерческая замена |
| [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) | Русский, потоковая генерация; варианты 0.6B/1.7B, управление голосом зависит от модели | Следующий кандидат, здесь не запускался. Для клонирования только разрешённый голос. У [0.6B Base](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-Base) указана Apache-2.0; размер и задержку нужно измерить на нашем железе |

Для первого сравнения Qwen3-TTS не менять лицо, текст, громкость и критерии одновременно. Иначе не поймём, улучшился голос или впечатление от другого персонажа.

## Альтернативы лица

| Решение | Что меняется | Где полезно, что ещё проверить |
|---|---|---|
| Наш атлас на основе [DH Live](https://github.com/kleinlee/DH_live) | Подбор готовых изображений вместо нового нейросетевого кадра | Уже работает на CPU; мало эмоций, конечный набор движений. Нужны права на образ и веса |
| [FeatherTalk](https://github.com/anliyuan/FeatherTalk) | Маленькая персональная модель создаёт кадры во время речи | Авторы предлагают CPU и C++/MNN, обучение по записи человека. Код Apache-2.0. Наше качество русского и скорость не измерены |
| [MuseTalk](https://github.com/TMElyralab/MuseTalk) | Генерация области лица по новому аудио | Проверять при доступном онлайн-GPU. Кэш подготовки не устраняет генерацию каждого кадра. Код MIT; авторы разрешают коммерческое использование модели, но отдельно ограничивают тестовые данные и лицензии зависимостей |
| [LivePortrait](https://github.com/KlingAIResearch/LivePortrait) | Перенос движений из управляющего видео на портрет | Вспомогательная подготовка движения головы. Сам по себе не завершённая замена аудиолипсинку. Новый путь «фото до нашего атласа» пока не проверен |

DH Live в текущем README заявляет MIT и отдельно описывает авторизацию демонстрационных образов. Наш старый пакет закреплён на [commit 4a90da6](https://github.com/kleinlee/DH_live/tree/4a90da6e32b9cef7ed850455eddc754abed8b454). Современный README не служит лицензией на любой старый вес или лицо. Для коммерческого выпуска проверить конкретные файлы и заменить персонажа на собственный согласованный образ.

## Как довести до полноценного диалога

Порядок будущих экспериментов, не выполненная часть защиты:

1. Подключить локальные VAD и распознавание к текстовому тренажёру. Проверить паузу внутри фразы, шум, речь на фоне ответа. Микрофон не должен распознавать собственный динамик: наушники и эхоподавление.
2. Подменить только текстовый API локальной Qwen. Оставить сценарий, собственную позицию роли, пол персонажа и отчёт. На одинаковых диалогах оценить уместность и следование роли.
3. Вместо полного WAV передавать короткие порции PCM. Держать TTS загруженным. Сохранить состояние аудиодрайвера между порциями; его текущие блоки по 0,8 с и калибровку проверить отдельно. Текущие 80 мс выбора состояний не считать задержкой всего ответа.
4. На событие начала речи пользователя остановить аудио, очистить очередь кадров, отменить LLM/TTS и повысить номер реплики. Все поздние порции старого номера отбрасывать. Smart Turn нужен для конца речи, не для решения «пора ли замолчать».
5. Измерить первые слышимые ответы и акустическое прерывание, затем сравнить лицо на тех же WAV. Цели первой приёмки, не результат: p95 прерывания до 250 мс; первого звука после конца реплики до 2 с. Если не укладываемся, уменьшить модель/буферы или разделить нагрузку на своей машине.

Для человеческого теста: одинаковые 10 реплик, одинаковая громкость, слепой порядок вариантов. Оценивать отдельно голос, губы и естественность лица по шкале 1–5; отмечать проблемный момент записи. Смыкания «п, б, м», округления «у, о», быстрые слова, числа, пауза, раздражение. Для прерываний минимум 20 попыток, медиана и p95, ложные срабатывания отдельно. Сравнивать с выбранными API-вариантами на тех же фразах, не по памяти.

## Ответы на неудобные вопросы

- «Это уже полностью локальный продукт?» Нет. Локальная мультимедийная часть проверена отдельно; автономный разговор пока спроектирован.
- «Вы просто проигрываете видео?» Нет. Аудио создаётся по новому тексту, а последовательность рта заново выбирается под этот звук. Сами изображения подготовлены заранее.
- «Лицо всегда будет таким живым?» Нет гарантии. Повторы и ошибки артикуляции возможны; нужен человеческий тест.
- «Бесплатно?» В тесте нет платежей API. Остаются оборудование, электричество, подготовка данных и сопровождение. Открытые веса не отменяют лицензионных ограничений.
- «Можно поставить у заказчика без интернета?» Демонстрационную часть да, с заранее установленными зависимостями и файлами. Полную систему надо собрать и проверить на его оборудовании.
